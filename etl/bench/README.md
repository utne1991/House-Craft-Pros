# etl/bench/ — Rust readiness benchmark (NON-PRODUCTION)

This directory holds the benchmark harness for Sprint 01 US10/T025/T028
only. **Nothing here is in the production run path.** The one production
ETL engine is TypeScript (`etl/src/`, driven by `etl/src/run.ts`).

## What is here

| Path | What it is |
|---|---|
| `ts-bench.ts` | TypeScript bench driver: parse + normalize + dedupe over the same fresh CSVs, writes canonical outputs + summary. |
| `rust-harness/` | Rust (std-only, no crates) bench harness implementing the SAME parse + normalize + dedupe rules, writing the SAME canonical outputs. Build with `cargo build --release`. |
| `run-bench.sh` | Runs both sides 3×, takes medians, byte-compares the outputs, writes `results-2026-11-25.md`. |
| `out/` | Benchmark outputs (canonical records/businesses/dedupe + summaries) — **written to `/tmp/hcp-bench-out` by default, never into the repo**, because the canonical records contain real licensee names/phones/addresses (PII). `run-bench.sh` respects `HCP_BENCH_OUT` to move them. |
| `results-2026-11-25.md` | The benchmark report (generated by `run-bench.sh`). |

## Parity rules (T028)

- Same CSV files (same SHA-256 — recorded in each `summary.json`).
- Same machine (CPU/RAM/OS/Node/Rust versions recorded in the results).
- Same normalization + dedupe rules and output schema (canonical JSON).
- Metrics: end-to-end time, CPU, RAM, output accuracy (row counts +
  checksum + diff, every delta explained). DB write speed is measured
  for the TypeScript production path only — the Rust harness builds no
  loader (no Rust engine in this sprint), and that limit is stated in
  the results instead of speculated about.

## Do NOT

- Do not import anything from `bench/` into `src/`.
- Do not point the production loader at the Rust binary.
- Do not treat a benchmark win as a decision to rewrite the engine:
  see `docs/architecture/rust-readiness.md` for the conditional
  recommendation.
