# Benchmark results — TypeScript vs Rust (Sprint 01, T028)

**Date:** 25/11/2026 · **Machine:** 4 CPUs, 7934 MB RAM, Linux 7.0.0-44-generic x86_64 GNU/Linux · **Node:** v24.22.1 · **Rust:** rustc 1.100.0 (0ef1bc386 2026-11-09)

**Parity:** same CSV files (SHA-256 in each summary.json), same machine, same normalization + dedupe rules, same output schema (canonical records.jsonl / businesses.json / dedupe.json). Scope: parse + normalize + dedupe only (the CPU-bound stages). The Rust harness has no database loader — DB write speed is TypeScript-only, see below.

## Results (median of 3 runs)

Figures are medians of 3 runs (the middle value), not best-of-3. (Correction
25/11/2026 after independent QA finding F1: an earlier draft reported the
minimum of the 3 runs as the "median".)

| Metric | TypeScript (Node 24) | Rust 1.100.0 (release) |
|---|---|---|
| End-to-end wall time | 2715 ms | 3227 ms |
| User CPU | 2900.755 ms | 3020.0 ms |
| System CPU | 484.273 ms | 180.0 ms |

## Output accuracy

All three canonical outputs are **byte-identical** between the two builds (run1), and stable across runs per side: 43,976 records, 43,895 businesses, 78 merged + 1,355 held dedupe decisions, 40,190 active / 3,786 expired / 0 unknown. **Zero unexplained deltas.**

## DB write speed

TypeScript load (psql COPY + upsert, one transaction per source, from the 25/11 dry-run): RMP 9,412 rows in ~6s end-to-end (incl. download+parse+normalize+dedupe), electrical 14,066 rows in ~9s, HVAC 20,498 rows in ~10s (wall, incl. ~2s download each). Rust DB write was NOT measured: the harness is parse+normalize+dedupe only and builds no loader (no Rust engine in this sprint).
